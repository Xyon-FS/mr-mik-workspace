# Mik’s Midnight Workshop

A public, offline starter for learning Mr. Mik: four sample cards, five HTML pages and one editable SVG. The fictional game is **Biscuit Bureau**, a midnight espresso delivery adventure with a very serious flat cap.

| Card | Contents |
| --- | --- |
| Welcome to the workshop | Start here, Field guide; pinned overview |
| The midnight espresso engine | Feature notebook, architecture, decision disclosure and example checklist |
| Caps, crumbs & characters | Art brief, palette, clickable/downloadable SVG, art-to-development handoff |
| Operation: one more biscuit | Pitch, launch beats, material table and reusable-process idea |

All metrics/tasks are explicitly illustrative. Checkboxes demonstrate HTML interaction and do not persist. No models, paid APIs or external services are needed to browse. The SVG is an original code-authored vector reference, not an imported game asset or generated 3D model.

## Add and customize

New portable packages and newly created installed-app Hubs include the example by default. Existing Hubs use **Workspaces → Add example workspace**. The source starter remains free of personal state and has the same button. Update installation does not silently seed existing Hubs.

Adding again while the example workspace exists selects it without replacing pages, card status, renamed workspace or custom shared styles. Delete the workspace and its cards to start fresh. If you choose Keep on removal, retained cards remain in Global Hub; re-adding creates new IDs/folders and does not reuse or overwrite those cards.

The example has `repositories: []`; its card chats use workspace planning. This is distinct from a workspace with missing linked folders, which needs relinking. You may add the first real external folder later. Native project MCP/plugin configuration needs a linked working folder; Hub skills/libraries still support workspace scope. No native MCP/skill configuration is created by the example.

## Storage and distribution

Sources are under `desktop/service/demo-assets/`. The installer copies only new UUID-named card folders and adds portable metadata. Missing shared `report.css`/`report.js` files are supplied without overwriting existing ones. No native settings, chat history or credentials are included.

Cards use `sample: true` to stay visible regardless of age; normal Archive/Restore/Delete still applies. Full/light Hub archives and content snapshots carry the pages, SVG, sample flags and example identity. A snapshot import remains subject to the normal conflict rules. Editing a demo and transferring it preserves your changes.
