# OpenCode V2 implementation status

Reference audit: official migration documentation and the `v2.0.21` source tag. Do not infer runtime compatibility from evolving documentation alone.

## Completed foundation

- Resolve the actual PATH-selected installation, including standard V1 and V2 npm wrappers. No UI version selector or exact version allowlist.
- Explicit `MRMIK_OPENCODE_BINARY` development override; use isolated configuration/data for tests, never real sessions.
- Portable layout `App/` plus `MyHub/`, legacy Hub recognition, external Hub argument, non-mutating launcher and matching release verifier.
- Legacy transfer detects V2 storage even when old V1 tables remain. No direct database writes or migrations.
- V2 runtime routing, private `--standalone` launch, native package entrypoint and context/event adapter. New native IDs are assigned before startup; V2 plugins can load after creation. Empty chats remain conversation-free until actual input/execution.
- Explicit isolated native smoke with CLI 2.0.21: private server, real stdio Workspace Bridge bootstrap, localhost mock provider, compact system orientation, exact native ID/activity/final preview and same-ID continuation after restarting the private server. Resuming alone does not replay a user message or invoke the mock provider. No personal auth/config/session data is used.
- ConPTY/native TUI acceptance: empty chat identity remains conversation-free, local prompt includes scoped orientation, close/reopen retains the exact native ID without prompt replay, and native fork receives a distinct verified ID. Fork creation uses the native private API before terminal startup, avoiding lost creation events during plugin loading.
- V2 History resume and MCP-restart preflight check the exact native ID through read-only database identity lookup. Missing IDs stop before terminal launch instead of triggering V2's implicit new-session creation. Unknown identity schemas fail safely; additional columns and later patch versions are not rejected.
- V2 TUI entrypoint uses native public catalog data and reachable command dispatch for model/variant/submit, and the native session interrupt API for Stop. Real ConPTY tests verify model/variant changes without restart, draft preservation, coordinator delivery, interruption, and picker recovery after a mocked provider failure at a resized terminal width. Readiness rejects permissions/forms, foreign routes, autocomplete and busy sessions. Invocation receipts are launch-scoped, bounded, sanitized and retained in ephemeral memory across plugin reloads to prevent duplicate dispatch.
- V2 configuration inspection/editor understands `mcp.servers`, inverse `disabled`, server replacement across layers, ordered skill permissions and configured skill-path arrays. New project overrides retain native options and environment/file references; sensitive literal credential fields require explicit configuration rather than automatic copying. Inherit removes an unchanged generated override, not an externally changed definition. Native smoke confirms the project override connects a local fixture MCP using its referenced header. Plugin package/directive declarations are visible read-only; actual plugin IDs are not guessed from package names.
- V2 account actions use positional `openai` integration and private native server flags. Status parses only metadata JSON into a fixed enum. Isolated native `auth list` verifies logged-out; login/logout command construction is tested without executing either or exporting credentials.

## Implementation checkpoints

The phase notes below record their status when each step completed; their “next” and packaging notes are historical. The final regression section and release-verification record describe the latest verified build. Remaining capability limits are not waived by successful fixture tests.

### Phase 1: native skill identity and attention — completed

Skill switches now address actual V2 IDs, independently of display labels. The file inventory covers singular/plural source folders, direct Markdown, nested `SKILL.md` and configured sources relative to the working location. Frontmatter metadata is parsed without storing instruction bodies in control receipts. Owned V2 terminals can provide the native metadata catalog, including sources already loaded by OpenCode; Mik does not fetch remote sources itself. Ask/allow/deny remain distinct for approval notices and guarded refresh fingerprints. Hub native suppression uses IDs. Native `form.created/replied/cancelled` and permission events track concurrent dialogs, so one reply cannot prematurely clear another pending request.

Verified against the isolated CLI 2.0.21 server and real ConPTY: native/local skill IDs match, metadata catalog controls exclude bodies, and form creation/reply changes attention without retaining field values. Unit regressions, frontend build and lint pass. This completes the first follow-up phase, not full V2 integration. Next: external/tool attachments; then guarded same-ID continuation replacement; then family/fork transfer and deletion. External file watching, auxiliary skill assets, CLI-only plugins and broader managed policies remain separate limits. Portable/installer builds remain unchanged.

### Phase 2: V2 attachments — completed

Prompt attachments already contain historical bytes; export preserves these bytes and normalizes URI provenance to an inline source, even if the original file has moved or changed. Tool file URIs use the existing metadata-only review and single-use explicit approval flow before local bytes are read. No automatic remote downloads or private-file reads. Changed files/chat receipts, unsupported media, symlinks/junctions and size limits fail closed. Imports require embedded content and native disposable-database validation. Tests cover end-to-end Hub archives, approval/expiry behavior, source preservation and a real native media round-trip into a separate DB. Installer/portable artifacts are not rebuilt. Next: guarded same-ID continuation replacement, followed by family/fork portability and deletion.

### Phase 3: same-ID continuations — completed

Exact-prefix incoming histories now report Update, while identical/older/divergent histories retain their previous protections. Native V2 import remains create-only; Mik implements a guarded standalone replacement, not a database upsert. Both incoming and original recovery imports are validated in separate disposable databases, then a durable verified backup and database/session-scoped Mik lock precede native deletion. Local policy is retained, exact source data is rechecked before mutation and result verification precedes History attachment. On command failure, native restoration is verified; foreign concurrent content is never deleted to force rollback. Unverified recovery keeps a lock and recovery backup, reports a manual-recovery error and must not be blindly retried. A crash can leave the lock/backup for manual inspection; this is not an automatic crash-recovery service or an atomic transaction across applications. Close all clients using the conversation, including outside Mik.

Real isolated native tests confirm same-ID continuation update, durable original backup and recovery after an injected post-delete import failure. Archive tests confirm updated History handling, older-branch preservation and divergent conflicts. Next: family/fork transfer and deletion. Desktop packages remain unchanged.

### Phase 4: families, fork portability and deletion — completed

Bounded parent/child families now transfer as one flat V2 envelope, in parent-first order. Every member must share the working folder, have unique message IDs, settled work and valid in-family tool references. Limits: 64 members, depth 16 and 64 MB combined JSON. Complete-family comparison preserves newer local data and rejects mixed/divergent branches. Replacement prevalidates and backs up the whole local family; partial import failure restores every original member. Fresh partial imports can be removed only after confirmed ownership and exact reviewed-content checks. Unknown/foreign results retain a recovery lock rather than deleting data blindly. Deletion previews enumerate every member, block separately associated History children, recheck the family hash and verify all planned IDs are gone after native recursive deletion.

Forks are independent native roots with copied, uniquely identified messages. Full export materializes their existing history and records source/boundary provenance as `info.metadata.mrMikFork`, retaining the conversation ID. Native import preserves the transcript and metadata, but does not recreate the native fork link or all operational instruction/snapshot state. Original forks are not silently included or deleted with their source's child family. Copied tool references outside the fork's own family remain guarded. Conflicting preexisting `mrMikFork` metadata is refused.

Unit/archive regressions cover family topology, same-folder scope, identity/reference checks, divergence and protected deletion. The isolated native fixture exercises copied fork transfer, parent/child/grandchild transfer, family updates, partial-import restoration/cleanup and recursive removal. `--transfer-only` focuses this fixture on transfer without running the separate form-attention probe. Final acceptance reproduced intermittent lost observer-state writes during Windows atomic replacement; bounded retries now retain the newest state without replaying requests. `--attention-stress` exercises twelve consecutive form/reply cycles, with identifier-only fixture diagnostics and no stored fields/answers. No installer/portable was rebuilt by phase 4 itself.

The V2 native adapter supports settled standalone and bounded same-folder family conversations via native `session export/import/delete`. Revert state, cross-location histories, queued/unsettled work and unsafe attachment references remain guarded. V1/V2 conversion is not implicit. These are format/capability limits, not version-number pins.

Verified V2 server-plugin identity controls are now implemented for owned open chats. The native plugin catalog supplies IDs/provenance; builtins, SDK components and Mik adapters are not controllable. Exact-ID exclusions can be added/removed through Tools and approved Bridge requests. This does not synthesize a package declaration to bypass inherited/global/wildcard exclusions, copy options, or persist/export identity proof. CLI-only TUI plugin policy remains outside these server controls. Isolated ConPTY smoke verifies the actual ID differs from the package name, then confirms native disable/re-enable without a model request. TypeScript and the frontend production build pass; desktop installer/portable packaging has not been rebuilt.

Native refresh foundation covers the declared Codex/Claude/OpenCode skill/plugin inventory and Mik editor notifications, with private fingerprints and guarded same-conversation resume. ## Running the isolated native smoke

Install the fixed audit fixture locally, not globally: `npm install --prefix .cache/opencode-v2 --no-save --ignore-scripts @opencode/cli@2.0.21`. Then run `node desktop/service/test/opencode-v2-native.mjs`. The script uses the platform package's executable directly and deletes its own isolated profile afterward. The downloaded CLI remains an ignored development cache; it does not replace the user's installation. The pinned fixture is reproducible test data, not a runtime version restriction.

Add `--tui` to exercise the real Windows ConPTY terminal, empty/new chat, model/variant selection, draft protection, native submit/interrupt, provider-failure recovery, close/resume and native fork against the same local fixtures. All fixture-owned terminal processes and profiles are closed/removed in `finally`; no personal app is restarted.
