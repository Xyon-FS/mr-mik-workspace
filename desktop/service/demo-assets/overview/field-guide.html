What is a card?

A card is a work-area collector, not a single HTML file. Keep related reports, references, diagrams and notes together. Here, Welcome has two pages; the art card has an HTML brief and an SVG source.

Workspace

The logical endeavor: Mik’s Midnight Workshop.

Linked project

An optional external working folder: for example Unity or Blender. None is connected in this demo.

Card

A focused area such as development, art direction or launch.

A realistic request

Explain the feature we just built and add an HTML report to this card in Mr. Mik. Then save the reusable lesson as Knowledge for this workspace.

Codex and Claude chats started through Mr. Mik can discover their scoped Workspace Bridge. Ask for a card in Mr. Mik to distinguish a Hub report from a file in the external working project.

Where does each thing belong?
  • Code and technical project instructions: the linked working folder.
  • Reports and supporting media: this card inside the Hub.
  • Reusable lessons: Knowledge.
  • Repeatable procedures: Processes.
  • Incoming references: Inbox, optionally associated with the workspace.

Try these small experiments

  • 📌 Pin the art card; it moves into Pinned.
  • Open the visual and try its full-size preview and download.
  • Archive a card, then use the left navigation’s Show archive to restore it.
  • Remove the example workspace: choose Keep, Archive or Delete for its cards.

Deleting the example and adding it again creates fresh examples. Adding while it still exists simply selects it; it does not overwrite your edits.
